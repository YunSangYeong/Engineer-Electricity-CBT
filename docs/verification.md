## Git와 수동 배포 안전 장치

초기 대상 저장소와 원격 main은 `11e717ecd84348fafce6c8477a3f4da76215b456`이며 README만 존재했다. 기존 workflow가 없음을 Git 트리로 확인했다. API로 Pages 상태를 확인할 수 없어 새 브랜치 `feat/engineer-cbt-20261021`를 만들었으며 사전에 원격에 없음을 `git ls-remote`로 확인했다. main으로 병합하거나 푸시하지 않는다.

`ci.yml`은 push/PR 검증 전용이며 배포 권한·단계가 없다. `pages.yml`은 **workflow_dispatch만** 받고 validate/deploy 둘 다 `github.event_name == 'workflow_dispatch' && github.ref == 'refs/heads/main'`을 요구한다. 에이전트는 수동 실행을 호출하지 않는다. 사용자는 main 병합 전 기존 Pages Source를 확인해 GitHub Actions로 설정하고, README의 수동 배포 절차를 따른다. 최종 커밋/원격 브랜치 반영 결과는 작업 완료 응답과 Git 이력으로 확인할 수 있다.

클라우드 환경에는 `npm ci → npm test → npm run build` 설치 스크립트와 개발 서버 시작·기능 검사·배포 금지 지침을 설정 초안으로 저장했다. 공식 도메인 3개 추가도 초안으로 저장했으나 런타임 적용·환경 게시·새 작업 복원 검증은 완료하지 않았다.
